# Instructions for coding and content-editing agents

This repository is a **personal scientific website** for Matthew Payne, astrophysicist and Director of the Minor Planet Center. Preserve the approved dark-to-light design and the lightweight, scientific aesthetic in `DESIGN.md`.

**Start here:**
- `docs/CONTEXT.md` explains why the site is built the way it is: audience, design intent, data sources and decisions already made. Read it before changing structure or content.
- `docs/ROADMAP.md` is the list of open work and content ideas. Pick up from there, and update it when you finish or add something.

## Principles

1. Accuracy before embellishment. Do not invent publications, institutional appointments, collaborators, mentees, scientific results, quotations, degrees or biography details.
2. Prefer first-party data and Matthew's original work. Source links must be verifiable; the MPC public tutorials are at `https://docs.minorplanetcenter.net/tutorials/`.
3. Do not use AI-generated human portraits as though they represent Matthew Payne. `public/assets/portrait-placeholder.svg` is deliberately an initials placeholder.
4. Simulations must be real physics, computed or validated, never decorative preset shapes. Physics animations are educational, not MPC ephemerides, and must say so.
5. Avoid stock astrophotography as filler; scientific plots should be sourced from the work or directly computed.
6. Maintain keyboard accessibility, semantic heading hierarchy, alt text, contrast and small-screen layouts. Nothing autoplays.
7. No server-side runtime is required. Keep all interactive experiments client-side so GitHub Pages works.
8. Protect private information and never include secrets (such as an ADS token) in the repository or client code.
9. Do not push to GitHub or change repository settings without Matthew's explicit go-ahead.

## Editing guide

- Intro and identity: `src/data/site.json`.
- Section titles, eyebrows and leads: `src/data/pages.json`. Research, People, Teaching, Software and Publications have their own pages in `src/pages/`; MPC still uses the generic `src/pages/[slug].astro`.
- Homepage cards: `src/data/features.json`.
- Research themes: `src/data/research.json`, which assigns every refereed paper (by ADS bibcode) to one of six themes or to `other`. When a new paper appears, add its bibcode to a theme; the build prints a `[research]` warning for any paper not assigned.
- Structured records (one YAML file each, validated by `src/content.config.ts`):
  - `src/content/tutorials/`: notebooks, linking to the authoritative MPC tutorial pages.
  - `src/content/courses/`: courses written or taught.
  - `src/content/software/`: a curated list chosen by Matthew. Do not add repositories on your own initiative.
  - `src/content/publications/`: refereed papers generated from NASA ADS by `tools/fetch_publications.py` (needs `ADS_API_TOKEN`). Do not hand-edit generated files except to set `featured: true`, which regeneration keeps. The ADS query is one Matthew confirmed; change it only with his approval. For anything ADS misses, copy `_TEMPLATE.yaml`.
  - `src/content/people/`: students and postdocs Matthew has supervised (`relationship: mentee`), using only details Matthew supplies or his CV; record where each came from in `source`. Copy `_TEMPLATE.yaml`.
- MPC staff: `src/data/mpc-staff.json`, from the MPC About page and its archived copies. Keep roles exactly as the MPC states them.
  The build fails if a record does not match its schema. Files starting with `_` are ignored.
- Collaborators: `src/data/collaborators.json` is generated by `tools/fetch_publications.py` from co-authorship (two or more shared papers with at most 40 authors). Matthew wants his co-authors listed; this is a factual record of shared papers and needs no further approval. Do not add roles, affiliations or relationship labels (such as "student") unless Matthew supplies them.
- Homepage: `src/pages/index.astro`. Shared site elements: `src/layouts/BaseLayout.astro`. Styles: `src/styles/global.css`.
- Homepage simulation: `public/js/orbital-lab.js`.
- Reference-frames tutorial: `src/pages/teaching/reference-frames.astro` and `src/scripts/frames/`. Initial conditions come from `tools/fetch_frames_ic.py`. Re-run `tools/validate_frames/` after changing the integrator, step or initial conditions, and update any numbers quoted in the page copy.

`preview/` is a stale dependency-free copy of v0.1 generated by `tools/make_demo.py`; the Astro source is authoritative.

## Before proposing or merging changes

1. `npm install` (Node 24; see `docs/CONTEXT.md` for the local Node set-up).
2. `npm run build` and `npm run check`.
3. Test changed pages and navigation at about 1440px and 390px widths, with no console errors and no horizontal overflow. A puppeteer-core script driving the installed Chrome works well for this.
4. For simulations: verify they run, pause and respond to controls, and re-run their validation.
5. Ensure no scientific or biographical placeholder content is presented as verified fact.
6. Update `docs/ROADMAP.md`.

## Architecture direction

Keep notebooks and tutorial code authoritative in their own repositories: MPC tutorials at docs.minorplanetcenter.net, and Matthew's own science notebooks in a separate `science-notebooks` repository (see `docs/ROADMAP.md`). This site links to them and hosts interactive browser adaptations, without silently duplicating divergent science.
