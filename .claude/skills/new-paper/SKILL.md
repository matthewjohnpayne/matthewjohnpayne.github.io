# New paper: $ARGUMENTS

First read `.claude/task-rules.md` (shared rules: never invent, verify sources, private data, real validated physics, accessibility, drafts, the GitHub issue, never push without Matthew's go-ahead) and `AGENTS.md`.

The publication records are generated by `tools/fetch_publications.py` (the weekly workflow may already have committed them). Do not hand-edit generated files except `featured: true`.

1. **Make sure the record exists.** Look for `src/content/publications/*.yaml` with `bibcode: "$ARGUMENTS"`. If missing, run `arch -arm64 python3 tools/fetch_publications.py` (it reads the ADS token from `~/.ads/dev_key`; never print it). Do not change the ADS query.
2. **Read the paper.** Abstract from ADS; the full text from arXiv (the LaTeX source when available). Note Matthew's role (author position) and the paper's main results, in its own words.
3. **Research theme.** Assign the bibcode to one of the five themes in `src/data/research.json`, or to `other`. Edit the file surgically (one bibcode added to one list); never rewrite it wholesale, and leave other uncommitted edits in it alone. The build prints a `[research]` warning for unassigned papers; it must be gone afterwards.
4. **Ask Matthew** (wait for answers):
   - Should it be `featured: true` (shown at the top of Publications and on the homepage)?
   - Does it merit a science-notebooks notebook, an interactive page on this site, both, or neither? Offer a concrete proposal: which figure or result could be reproduced, how long it would run, what data it needs.
5. **If a notebook is wanted** (repository `~/git_repos/science-notebooks`, read its `AGENTS.md`): one folder `notebooks/<name>/` with `<name>.ipynb` and a helper module (multiprocessing workers in the module); generate it from `tools/build_<name>.py`; execute with `tools/execute.py`; a `QUICK` flag if a full run exceeds about a minute, caching to `cache/` and `cache_quick/`; MPC tutorial style (title, author line, motivation, numbered "We will" list, numbered sections, Summary, Going Further, References); every figure computed, checked against the paper, differences stated; references checked in ADS; commit with outputs; add a row to its README.
6. **If an interactive page is wanted:** follow the existing pattern (e.g. `src/pages/teaching/heliolinc.astro`, `src/scripts/heliolinc/`, `tools/export_heliolinc_data.py`, `tools/validate_heliolinc/` with `reference.py` and `compare.mjs`). Port the notebook's physics, validate against it, quote the agreement on the page, add a `src/data/page-status.json` entry and `<PageStatus page=... />`.
7. **Cross-links:** the paper's theme links in `src/data/research.json`, a tutorials YAML in `src/content/tutorials/`, and the software or object pages where relevant.
8. Checks, issue (search for "$ARGUMENTS"), commit (both repositories if both changed), and ask before pushing - science-notebooks first, as its notebook links must resolve before the site links them.
